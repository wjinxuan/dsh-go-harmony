# dsh-Go 全量鸿蒙移植

## 目标

用户要求以 Android dsh-Go v1.0.15 为基准，全部页面、文案、交互和功能逐项一致，同时直接在鸿蒙手机运行 DeepSeek Harness。复刻验收覆盖真实操作结果，不以存在页面或按钮代替功能完成。基线提交为 `a9877420ab9aee121134faf01b6a92a39ce0b05b`。

## 已有架构

当前应用是 ArkTS / ArkUI Stage 工程，使用原生页面、DSH Web RPC / mux 和应用进程内的 Node.js 24.22.1 / DSH 0.2.2-rc.1。此前的手机本机文本对话、历史保存已经在 Mate 60 Pro+ 验证。本批新增原生导航、会话操作、消息渲染、模型/设置、工作区文件以及插件、技能、任务、调度、子代理入口；各项当前实现和验证边界见 [原生重写进度](native-progress.md)。

八组功能已进入集成验收，逐项实现与开发环境结果见[最终清单](full-implementation-checklist.md)。本机已接入受限工作区工具、原生插件桥、媒体、SenseVoice、DS Bot、伙伴回忆和安全删除；任意子进程、外部原生 Node 插件、任意安装脚本及本机 Shell 仍受手机沙箱限制。新增能力不能据宿主测试推定已通过真机验证。证据与此前真机记录见 [架构记录](../architecture.md)。

## 实施顺序

1. 固定原版版本、完整页面及功能清单，标记已有、缺失、平台限制与未验证。
2. 完成所选 UI 技术路线的最小真机验证：原版导航及页面能够渲染，并连到已经验证的手机本机引擎。成功前不替换用户可用的版本。
3. 对齐主题、文案、导航、引导、会话和消息渲染；补齐模型、设置、工作区和会话操作，检查修改后的真实持久化结果。
4. 补齐 SSH、加密 Remote、插件桥、工具、任务、终端、文件和分享；各主机按实际能力分别验收。
5. 移植媒体、通知、后台、跨应用操控、宠物、社区等系统或服务能力。公开平台不支持的项目保留明确差异记录，不使用返回成功的空实现。

## 验收

每个入口至少覆盖正常、空白、加载、错误、断线/恢复和返回行为；有状态的操作验证重新打开和重新启动后的结果。原版与鸿蒙版使用相同测试数据、视口尺寸、语言和主题作截图与交互对照。视觉一致和功能一致分别记录。

引擎改动必须回归启动、停止、再次启动、首轮流式消息、历史重开、文件锁、首次会话原子保存、网络失败和凭据清除。Key 由用户在手机输入；测试和报告不得收集 Key、Cookie 或签名配置。安装沿用现有包标识与签名，覆盖安装保留数据，不通过卸载解决构建或兼容问题。

终端、手机操控、后台执行、通知、文件选择等需在鸿蒙手机验证；桌面构建、单元测试或截图不足以将其标为完成。早期构建曾完成真机首轮和文件操作；当前最终构建不沿用此前手机验收结论，按[八组真机清单](phone-acceptance.md)重新验证。
