# dsh-Go v1.0.15 鸿蒙平台能力核对

对照 dsh-Go v1.0.15（`a9877420ab9aee121134faf01b6a92a39ce0b05b`），目标为标准手机 HarmonyOS 7.0.0（API 26），使用 DevEco Studio 26.0.0.851。页面与交互见 [界面核对](ui-audit.md)，当前项目在 Mate 60 Pro+ 上的本机引擎和对话验证见 [移植架构](../architecture.md)。

## Flutter OHOS

- 上游 CI 使用 Flutter 3.47.7，`app/pubspec.lock` 要求 Flutter `>=3.47.0`、Dart `>=3.13.5 <4.0.0`。本机常用 Flutter 是官方 3.41.6（Dart 3.11.4）和 3.44.1（Dart 3.12.1），两者均缺少 OHOS 构建命令、模板和引擎。 [上游 CI](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/.github/workflows/ci.yml) · [上游依赖锁](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/app/pubspec.lock)
- OpenHarmony Flutter 的 `3.47.7+ohos-0.0.1-pre`（`650641656fef1d0578f0bc1ed8f7a35087fc99f3`）基于官方 Flutter 3.47.7，Dart 提交 `04bcd1036cdc799ac6564988f159ee454d42c822` 与 Dart 3.13.5 标签一致。隔离目录中的 `flutter --version --machine` 和 `dart --version` 确认 fork CLI、Dart 3.13.5（macOS arm64）可运行。CLI 提供 `flutter build hap`，`flutter create --platforms=ohos` 已成功生成 HarmonyOS Stage 模板。 [Flutter OHOS fork](https://gitcode.com/CPF-Flutter/flutter_flutter/tree/oh-3.47.7-preview) · [Dart 3.13.5](https://github.com/dart-lang/sdk/tree/3.13.5)
- fork 读取的 OHOS 引擎版本为 `e401a687701deae526fb771d9b696f10c4b7d039`。仓库的 macOS arm64 Dart、主机工具和 OHOS arm64 debug HAR 可下载。发布模式的 `gen_snapshot` 下载包内是 macOS x86_64 可执行文件，对应 arm64 下载地址返回 HTTP 404，本机执行 x86_64 测试也返回 `Bad CPU type in executable`。当前 Apple Silicon 环境的 AOT 发布构建还需可运行的宿主工具，例如经验证的 x64 构建机或适配的 arm64 产物。 [Flutter OHOS 工具缓存源码](https://gitcode.com/CPF-Flutter/flutter_flutter/blob/oh-3.47.7-preview/packages/flutter_tools/lib/src/flutter_cache.dart)
- 隔离目录中对上游原始 `pubspec.yaml` 和 `pubspec.lock` 执行 `flutter pub get --enforce-lockfile` 成功，锁文件 SHA-256 保持一致。最小模板执行 `flutter build hap --debug --target-platform=ohos-arm64` 时，Hvigor 生成 96 MiB 未签名 HAP，ZIP 完整性验证通过，包内含 `libflutter.so`、`kernel_blob.bin` 和 `modules.abc`。Flutter CLI 随后因缺少调试签名退出码为 1。未安装模板 HAP，也未构建上游完整应用。
- Dart 页面、Riverpod 状态、主题、国际化、手势、`dartssh2`、`xterm` 和协议可在 Flutter 方案中复用，仍须重做 `dsh/runtime`、`dsh/files`、`dsh/share`、`dsh/notify` 等原生桥并验证第三方插件的 OHOS 实现。本项目按用户要求以 ArkTS/ArkUI 原生重写，使用这些上游代码核对页面、交互和协议。 [上游 Flutter 依赖](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/app/pubspec.yaml) · [运行时通道](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/app/lib/runtime/runtime_bridge.dart)

## 能力与设备限制

| 能力 | 鸿蒙手机上的实现和验证边界 |
| --- | --- |
| 本机引擎、会话与工作区 | 本项目已验证 HAP 内原生模块启动应用内 Node，并在手机完成真实 DeepSeek 对话。保留本机沙箱内的会话、工作区、模型配置和引擎生命周期。原版使用 Android 前台服务、PRoot、Ubuntu rootfs 和 glibc 可执行程序。鸿蒙公开的 Native 子进程在手机返回 801，HAP 内独立执行 bin 面向 PC/2in1，外部 .so/.bin 的 `ALLOW_EXTERNAL_NATIVE_CODE` 同样仅面向 PC/2in1。 [子进程 API](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-app-ability-childprocessmanager/) · [HAP 可执行文件](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/hap-bin/) · [受限权限](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/restricted-permissions/) |
| SSH | 上游 SSH 密码、私钥、主机指纹校验、远端命令、keepalive 和 TCP 转发依赖纯 Dart 的 `dartssh2` 和 socket。Flutter OHOS 可保留该实现。ArkTS 也可使用 Network Kit TCP 搭配经过适配的 SSH 实现，凭据使用 Asset Store 或 HUKS 保护。需在真机测主机指纹拒绝、两种认证及转发。 [上游 SSH](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/app/lib/remote/ssh/ssh_transport.dart) · [TCP API](https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-socket/) |
| 终端与 PTY | 原终端界面使用 `xterm`，`terminal/*` 协议由引擎创建和管理终端。远端 PTY 可保留，手机仅渲染、发输入和调整行列。NDK 头文件包含 `openpty`、`forkpty` 和 `posix_spawn` 声明，手机上应用沙箱能否执行被调用程序是独立问题。通用本地系统 shell 的等价性未得到公开能力支持。应用内实现沙箱命令或解释器可以提供本机终端交互，具体命令和行为按实现核对。 [上游终端协议](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/packages/dsh_client/lib/src/terminal_api.dart) · [原生子进程限制](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/capi-native-child-process-h/) |
| 插件、技能与 DS Bot | 插件列表、配置、状态条、工具卡、聊天菜单、面板和 DS Bot 等由 Dart、插件桥协议与引擎共同实现，可移植到远端和本机。可在 HAP 内打包经过验证的 JS 插件，继续使用 `/dsh-go/v1/*`。上游包含调用外部可执行程序、系统权限、原生 Node 模块的插件，本机需逐个审核运行依赖。动态插件和子进程仍关闭。本批启用应用内的受约束文件、技能和子代理工具；文件读写编辑已在手机验证。 [插件桥](https://github.com/ccch1mneyyy/dsh-Go/tree/v1.0.15/runtime/bridge/dsh-go-bridge) · [插件协议](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/docs/design/native-plugins-protocol.md) · [外部原生代码权限](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/restricted-permissions/) |
| 文件、附件、导入导出与分享 | 使用 Core File Kit 沙箱和 `DocumentViewPicker.select/save`、PhotoAccessHelper、Share Kit、Want URI 授权；可复刻对话导出、附件、ZIP 导入、私钥导入、图片保存、预览和系统分享入口。公有目录由系统选择器授权，文件夹选择和持久授权先按设备能力探测。上游也没有一键备份整个 Linux 环境。 [文件选择](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/select-user-file/) · [文件授权](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/file-persistpermission-V13/) · [系统分享接收](https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/share-kit-faq-0001/) · [上游本机引擎指南](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/docs/guide/zh/03-engine-hosts.md) |
| 手机操控、前台节点与手势 | 上游依赖 Android AccessibilityService 的窗口树、手势和截屏。HarmonyOS SDK 仍保留 `AccessibilityExtensionAbility` 类型，华为文档说明连接、事件、按键回调相关能力自 API 12 起不可用。Native 输入注入和 `CONTROL_DEVICE` 权限明确面向 PC/2in1。可实现 Deep Link、分享、受支持的意图、人工确认与视觉辅助。标准手机应用没有已确认可用于等价跨应用手势注入和窗口树控制的公开接口。HDC UITest 是外部开发调试能力。 [无障碍扩展](https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-application-accessibilityextensionability/) · [输入注入](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/capi-oh-input-manager-h/) · [受限权限](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/restricted-permissions/) · [UITest](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/uitest-guidelines/) |
| 截图、悬浮宠物与不打扰模式 | 自己窗口可截图。区域截屏可通过系统选择器，录屏可经系统授权。全屏静默截屏涉及定制截屏或录屏权限，公开静默录屏权限面向 PC/2in1 和 TV。上游不打扰模式依赖 Android 的 Shizuku、Sui、Root 或自连 ADB，属于不同的系统接口。手机任意跨应用悬浮宠物、后台静默操控和无障碍自动恢复未找到同等公开能力。应用内宠物、正常通知或合规画中画可单独移植。 [截屏](https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-screenshot/) · [录屏](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/avscreencapture-c-basic-process/) · [悬浮窗与录屏权限](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/restricted-permissions/) · [上游手机操控](https://github.com/ccch1mneyyy/dsh-Go/blob/v1.0.15/docs/guide/zh/04-phone-control.md) |
| 后台、通知与更新 | 可使用短时任务保存状态、系统代理上传下载、定时提醒、普通通知与回到会话入口。后台任务按业务类型校验。手机计算类长时任务需 `KEEP_BACKGROUND_RUNNING_SYSTEM`，公开场景为商家自动接单。持续服务的 `AppServiceExtensionAbility` 是 PC/2in1 企业应用 ACL。Android 前台服务、厂商自启动和 APK 安装流程需采用鸿蒙系统流程。引擎在后台连续运行、锁屏、进程回收和恢复需真机验证。 [后台长时任务](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/continuous-task/) · [后台服务](https://developer.huawei.com/consumer/en/doc/HarmonyOS-Guides/app-service-extension-ability/) · [普通通知](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-notificationmanager/) |

本机的 DSH 权限预设控制会话文件写入和审批策略。应用固定工作区路径的检查独立于预设，`danger-full-access` 仍受该路径限制。宿主回归已在该预设下实际提交并拒绝绝对路径写入、父路径文件创建及符号链接写入。Shell 服务只供 DSH 读取默认权限模式，执行和解析入口都会拒绝调用。新加入的模型提问、待办、目标和内存全文搜索均在应用进程内运行，已用打包引擎做宿主验证。 [权限服务](../../runtime/workspace-shell-policy.mjs#L4) · [文件限制](../../runtime/workspace-fs.mjs#L35) · [工具回归](../../tests/local-engine-smoke.mjs#L195)
